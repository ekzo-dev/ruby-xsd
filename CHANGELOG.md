## [2.9.4] - 2026-10-26

### Added

- RBS signatures in `sig/`: `xsd.rbs` from `rbs prototype rb` of `lib/`, and `xsd_members.rbs` with the readers that
  `BaseObject.property`, `.child` and `.link` define for each class (`Element#name`, `#complex_type`, `#max_occurs`

## [2.9.3] - 2026-10-24

### Fixed

- A schema with no target namespace that imports another namespace (an XMLDSig `Signature` referenced as
  `ds:SignatureType`) now finds what it imports. `Schema#targets_namespace?` took a namespace URI for a prefix, looked
  it up among the schema's prefixes, found nothing, and matched that nothing against the absent target namespace:
  every reference by a prefixed name was looked for in the schema itself.

### Changed

- Every import of the absent namespace is read from its own location. Schemas with no target namespace are each a
  schema of their own (a provider's documents, every one shipping its own copies of the common types, which may
  differ), so a second import of the absent namespace was not the same schema as the first one; before, it was
  answered with whichever such schema had been loaded first. An import whose location is loaded already is answered
  with that schema in any namespace (`XML#loaded_schema`); an import of a named namespace is still answered with a
  schema known for it before its location is read.

## [2.9.2] - 2026-10-21

### Changed

- A property, link or child of a schema object (`name`, `type`, `max_occurs`, `complex_type`, …) is read through a
  method of its own, defined when the class declares it, instead of `method_missing`, which costs far more per call.
  The lookup order is the same: a method a class or an ancestor defines itself still answers first, and
  `respond_to?` answers as before. Reading XML against a large schema runs about 40% faster under YJIT.
- `data_type` of an element, attribute, simple and complex type is worked out once and kept: the schema does not
  change once read, and converting a document asked for it once per value.

## [2.9.1] - 2026-10-20

### Changed

- A reference by name (a `type`, `ref`, `base`, …) is looked up in an index of the schema's top-level declarations
  (`Schema#declaration_node`), built on the first lookup, instead of an XPath query that scanned every child of the
  schema again for each reference. Large schemas referenced thousands of times are read several times faster
  there; what is found is the same.
- The specs no longer load `wasabi`, which only a commented-out example used and which does not load on Ruby 3.4
  (it requires `kconv`): the suite runs on Ruby 3.4.

## [2.9.0] - 2026-10-18

### Changed

- A schema with no target namespace included into one that has a namespace ("chameleon" include) is seen through
  a view in the including namespace (`XML#chameleon`, `Schema#chameleon?`, `#chameleon_source`). Everything it
  declares reports that namespace (`namespace`, `absolute_name`, `Schema#target_namespace`), and an unqualified
  name inside it resolves in that namespace. Before, its definitions reported no namespace at all.
- A schema included into two namespaces declares two sets of definitions, one per namespace: a view keeps its own
  object cache (`Schema#object_cache`), where one object per node used to serve both.
- `XML#schemas_for_namespace` returns what the schemas of the namespace include as well, chameleon views among
  them, and so does the lookup of a referenced name: includes of includes, and what a schema reached through an
  import includes (only the schema itself, or one level of includes, was searched). A schema only seen through a
  chameleon view is no longer among those of the absent namespace
- `XML#[]` and the collectors (`elements`, `complex_types`, `simple_types`, …) go through the schemas that stand
  on their own (`XML#standalone_schemas`): a schema only seen through a chameleon view contributes its
  definitions through the schemas including it, not a second time in the absent namespace

### Added

- `XML#target_namespaces`: every namespace the schemas declare definitions in, includes resolved; the absent
  namespace (nil) only for a schema with no namespace that nothing includes

## [2.8.1] - 2026-10-18

### Fixed

- An import/include location written with backslashes (`import\types.xsd`) is resolved as one written with

## [2.8.0] - 2026-09-21

### Fixed

- `XSD::XML.open` resolves relative import/include locations against the schema they were read from, so the default
  resource resolver no longer requires a custom one for ordinary multi-file schemas
- `Schema#validate` writes included schemas into the temporary directory too, so schemas wired together with
  `<xs:include>` can be validated
- `Schema#validate` serializes the temporary schemas as UTF-8, so schemas in another encoding no longer fail to load
- `XML#logger` no longer raises `NameError` when no logger is configured (`logger` was never required)
- `BaseObject#parent` returns `nil` instead of raising when the parent node has no XSD object (document, `wsdl:types`)
- `object_by_name` passes the searched name as an xpath variable instead of interpolating it into the expression
- `ComplexType#mixed_content?` and `#data_type` no longer raise on a `complexContent`/`simpleContent` without a
  derivation
- An `<xs:include>` of a schema without a target namespace ("chameleon" include) is accepted
- Import/include cycles no longer yield duplicated definitions
- The compiled validator no longer leaks an open file descriptor
- `Element#attributes?` and `ComplexType#complex_content?` return booleans instead of the underlying objects
- Import/include error messages name the namespaces that did not match
- `require 'xsd'` defines `XSD::VERSION`, which previously needed `require 'xsd/version'` on top of it

### Changed

- Imported/included schemas are loaded once per location and shared, instead of being re-read and re-parsed for every
  reference to them
- Property, link and child lookups cache `nil` and `false` results, which cuts repeated xpath searches (roughly 2.5x
  faster traversal of the bundled example schemas)
- `XSD::XML#add_schema_xml`/`#add_schema_node` accept a `location:` keyword, and `Schema#location` exposes it
- `XML#object_cache` is keyed by node identity (`Hash#compare_by_identity`) rather than by `node.object_id`, which
  lets the `Lint/HashCompareByIdentity` rule be enabled again
